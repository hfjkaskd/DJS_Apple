# 丰收奖励：游戏内分步流程

奖励入口采用已确认的 [v3 绿色钞票效果稿](HarvestUIConcepts/harvest-rewards-ui-v3-money.png)：独立领奖弹窗、游戏 HUD 和七个钱包页面按余额、目标和阶段组织操作，玩法仍是水果三消。

## 玩家操作

1. 首页、关卡、胜利页显示丰收余额和提现入口。未申请时显示距离目标的差额；申请后显示当前阶段和任务数量。
2. 新手礼物、局内奖励、过关奖励分别使用小弹窗。领取后返回所在的游戏页面；不再自动打开钱包。关闭未领取奖励不会删除它，原账本的补领规则仍有效。
3. 点击提现进入选档页，六档金额按两列三行排列：1,000 / 1,500 / 3,000 / 5,000 / 8,000 / 10,000。选中档显示描边和勾选，余额差额、进度条和百分比随档位更新；余额不足可继续游戏。
4. 余额足够后进入确认页，说明冻结金额、六阶段、最终等待及最短总时长。点击确认才创建申请。
5. 申请后显示冻结的申请金额、当前任务、任务进度、阶段节点、当前倒计时和继续游戏按钮。三消任务显示三个水果，通关任务显示关卡图标；关闭后再次打开会恢复到当前进度。
6. 六阶段结束进入最终等待页；时间到后显示模拟完成，结果进入记录页，可以选择下一档。
7. 完整规则单独查看，返回后回到原来的流程页面。

## 保留的核心

- 原有奖励数值、首次免费倍率、累计奖励减速、六个金额档位保持不变。
- 六阶段仍为：通关 10 关、完成 260 次水果三消、通关 10 关、完成 300 次水果三消、通关 10 关、完成 500 次水果三消。
- 每阶段任务和 24 小时计时都完成后才进入下一阶段，最后再等待 168 小时，最短 13 天。任务与计时并行，只有当前阶段的新游戏进度计数。
- 一次一个申请，申请金额从可用余额转到冻结余额，每档完成一次。跨会话恢复、时钟回退检查及存档保护保持不变。
- 仍为明确标注的模拟奖励，无现金价值、不收集支付账户、不执行真实打款。广告 SDK 未连接时显示不可用，不伪造广告成功。

## Unity 配置

- `Assets/res/local/harvest/HarvestRewardsUI.prefab`：七个静态页面，控制器只负责状态切换、文字刷新和事件绑定。
- `Assets/res/local/harvest/HarvestRewardPopupUI.prefab`：独立领取卡片。
- Home / CorePlay / Win Prefab 的 `HarvestRewardsHUD`：余额入口、目标进度条和六节点。
- `Assets/res/local/harvest/sprite/HarvestCash.png`：独立绿色钞票 Sprite，用于 HUD 余额、六档金额、领奖、申请、等待、完成及记录页面。三消任务继续引用原有 `Fruit_4`，棋盘水果与普通金币资源保持独立。
- CorePlay 的水果放在 `Game/Map/Layer`，Map 的位置和缩放为顶部 HUD 留出空间；背景和收集篮独立保留。水果在棋盘与篮子间切换时归一根缩放，避免入篮、撤回及存档恢复出现尺寸差异。
- `Assets/Resources/HarvestRewardConfig.asset`：原有经济、阶段和时间配置。
- `Tools/GenerateHarvestRewardsUI.py`：离线重建静态 Prefab，调用 `HarvestFlowPrefabs.py`。美术结构写入资产，运行时不动态构建界面。
- `Tools/GenerateHarvestSkins.cjs` / `Tools/HarvestSkinSources`：可编辑 SVG 源与离线 PNG 导出。17 张小型专用皮肤配置九宫格边界，面板、档位、进度条不再复用不适合此比例的旧切片。
- `Assets/res/local/harvest/fonts`：Lilita One 标题、Nunito ExtraBold 正文；两个静态 SDF 图集、四个共享材质。原字体和 OFL 许可随资源保存，`HarvestFontAuthoring.BuildAll()` 可重新烘焙，无运行时字体生成。
- `HarvestReferenceLayout`：对整体 DesignRoot 等比缩放，单独将遮罩铺满 Canvas；顶部与底部安全区不再留下亮条。`HarvestHudFit` 仅在窄屏等比缩小静态 HUD，保留水平边距。

页面使用奶油色卡片、橙色标题条、绿色主按钮和浅色辅助按钮。标题由七页的 `pageTitles` 配置；额度使用钞票图标，任务使用相应玩法图标。所有新点击控件均为标准 Button，事件在代码绑定。HUD 和钱包按事件及每秒节奏刷新，领取卡片每 0.25 秒检查短等待和广告状态。

领奖卡展示普通领取后的预计余额，实际入账仍以成功领取为准。新手礼物已经入账时只显示当前余额；广告进行中也显示当前余额，不提前计入广告奖励。整数档位省略小数，余额保持两位小数；未达到目标时百分比最多显示 99%。

钱包的 Rules / Records 居中独立排列；详情页使用 Back / Rules / Records 三按钮栏。未领取奖励与钱包流程说明共用一个位置。HUD 未申请时显示进度条，申请后同一位置显示阶段节点。规则正文从顶部左对齐开始，异常状态使用独立提示区域。所有布局均可在 Prefab 编辑。

## 验证

此前流程版本已通过 Unity 脚本编译、21 项领域回归及 26 个布局检查，并在实际游玩中验证过关弹卡、关闭后补领、单次入账、待领取入口移除和重新运行后的余额保存。

v3 验证入口仍为 `HarvestRewardValidation.ValidateAndRender`，生成 28 张布局截图：七页长短屏、三类领奖卡、三个 HUD 的两种状态、长金额与已完成档位、通关任务，以及两张棋盘极值图。新增检查读取实际 Prefab 的六个 Button 矩形，验证两列三行、顺序、间距和标签归属；检查钞票 Sprite 的专用引用、三个任务水果与任务根引用。截图使用余额 247.61、首档 1,000 和三消进度 86 / 260，额外保留 9,750 / 10,000 的长金额状态。

原有标准 Button、引用完整性、文本溢出、生产 CanvasScaler 与安全区检查保留。棋盘检查仍读取主线与保底关卡配置中的本地资源，并验证水果与 HUD、篮子的间距，以及换父、撤销和恢复尺寸。此前覆盖 1668 个本地配置、208929 个水果矩形；尚未提供本地文件的关卡不包含在资产审计内。v3 编译和渲染结果以本轮 Unity 批处理日志为准，未执行真机或真实支付测试。

`HarvestRewardValidation.RenderReferenceComparison` 以 1119×2268（参考画幅 373×756 的三倍）导出四张对照图。使用实际 Map1008 与第四关水果，仅为截图设置示例状态，不改玩家存档；产物与效果图并排展示在 `Docs/HarvestUIConcepts/UnityReference/review.html`。本轮验收结果见同目录 README。
