# 丰收奖励计划 · 提现机制适配方案

版本：2026-09-14。适配基线：`425f0d5a31c2c5e30490785d685f69d671437ee3`。

本文是写入工程的产品方案和开发接入规格，尚未实现游戏内提现功能。金额沿用原报告的美元数值口径，但均为模拟奖励，不可兑换现金。玩家可见界面必须明确标注这一点，不能以银行审核、订单销售、真实到账等文案解释模拟流程。

## 1. 核心与主题

主题为“丰收奖励计划”：水果入篮、三消收获、领取丰收礼包、积累模拟奖励、开启六站丰收挑战、完成等待、模拟结算。

保留原方案的前期快速积累、主动广告加奖、自动广告变现、活跃分层、六阶段任务与等待，以及首次达标后减速。所有门槛、任务和等待在申请前一次性展示，不在用户达标后追加条件。

不增加种植、经营、交易或物流系统；“丰收”只包装现有水果三消玩法。原游戏金币继续用于原游戏资产系统，丰收模拟余额独立记账，不将现有金币变成美元。

## 2. 已核实的工程内容

| 工程事实 | 对本方案的影响 |
| --- | --- |
| `EDLHEMMBABM.TryTripleMatch()` 每次匹配三个同类水果，增加 `eliminatedItemCount` 和 `elimGroupCount` | 统计单位用“三消组”，一组为三个水果；不按点击次数发奖 |
| `JEFOMCDAPGK.LevelWin()` 增加主线胜场，`CurMainLevelIndex` 为胜场加一 | 提现任务使用主线通关，不强行加入 Normal / Hard / Expert |
| `CorePlayUI` 有篮子、金币和撤销、魔法、洗牌、扩容入口 | 复用页面风格，奖励入口单独配置，不覆盖原金币入口 |
| `WinUI` 有宝箱进度、广告金币和下一关；`LevelBoxProgress`、`LevelBoxReward` 已存在 | 丰收奖励作为结算独立区块，原宝箱进度和金币奖励保留 |
| `LoseUI` 有首次免费复活与后续广告复活；`RealRevive()` 撤回最多三个入篮水果 | 使用现有复活行为，不承诺“整理整个棋盘” |
| `AdButtonState` 当前直接触发按钮回调，`WinUI.OnADPlayBtn()` 直接加金币 | 不能把点击当作观看成功；上线广告功能前必须接入真实 SDK 完成回调 |

仓库 README 将工程描述为开发资产库；虽然部分玩法方法已有实现，仍需逐项验证运行与服务接入。本文不将类型、按钮或 SDK 文件的存在视为功能已完成。

## 3. 六站丰收挑战

六档模拟门槛保持为 1,000 / 1,500 / 3,000 / 5,000 / 8,000 / 10,000，全部使用同一任务链。

| 阶段 ID | 玩家名称 | 开启后新增任务 | 等待 |
| --- | --- | --- | --- |
| `harvest_01` | 初次丰收 | 主线通关10局 | 24小时 |
| `harvest_02` | 收获积累 | 累计完成260组三消（780个水果） | 24小时 |
| `harvest_03` | 进阶丰收 | 主线通关10局 | 24小时 |
| `harvest_04` | 持续收获 | 累计完成300组三消（900个水果） | 24小时 |
| `harvest_05` | 丰收高手 | 主线通关10局 | 24小时 |
| `harvest_06` | 丰收总挑战 | 累计完成500组三消（1,500个水果） | 24小时 |

每阶段从开启时开始计时，任务与计时并行，两者均完成后才开启下一阶段。第六阶段完成后立即开始168小时结算等待，不额外增加一天。最短历时为六个24小时加168小时，共312小时，即13天；任务耗时超出阶段计时则顺延。缺席不清空已完成进度。

三次通关任务都走已有主线，随主线推进经历原关卡配置；阶段名称不代表新增的难度模式。原260/300/500的数字先按“组”保留，只保留计数级别，并不意味着操作成本等价：原一对两个对象，新一组三个对象，实际完成时间必须用关卡数据和试玩验证后调整配置。

### 统计边界

- 阶段开启前的通关和三消不追溯；未来阶段不提前累积；等待结束前产生的超额任务量不结转。
- 只统计实际确认的主线胜利和已提交的三消逻辑事件。一次三消加一组，不在动画结束、特效回调再加一次。
- 教学不计任务；重试中的新三消可以计入，重复读取快照、重放同一组、重复结算不可重复计入。
- 正常使用道具形成的三消可计入；单纯撤销、扩容、洗牌动作不计组数。任务不要求复活、不要求看广告。
- 一个申请同时只有一个活动阶段。一个用户同一时间只开一个申请，防止不同档位共用任务导致重复结算。

### 原文未规定的闭环：本版补充约定

选择达标档位申请后，将对应模拟金额从可用余额转入冻结余额；任务期间新增奖励仍进入可用余额。最终等待结束后扣除冻结额并生成“模拟结算完成”记录，绝不显示“现金到账”。每个档位完成一次，全部完成后显示计划已完成。

申请前可自由退出。申请后不因断登重置；若以后增加主动取消，必须明确冻结额退回规则，并记录取消后的任务进度处理。本版暂不提供取消入口。冻结、单申请和单档一次均为本版新增的确定性产品规则，不声称来自原报告。

## 4. 丰收奖励与经济节奏

| 场景 | 不看广告 | 主动激励成功 | 首次规则 |
| --- | --- | --- | --- |
| 教学完成 | 模拟奖励20 | 不设置激励 | 生涯一次 |
| 局内丰收礼包 | 模拟奖励5 | 10 / 20 / 30 / 40 | 首次免费×2 |
| 本轮丰收结算 | 模拟奖励10 | 20～100 | 首次免费且必定×10 |
| 道具补给 | 使用已有道具 | 按现有道具类型配置补给 | 不凭空增加“提示”道具 |
| 失败续玩 | 重试或符合原条件的首次免费复活 | 调用已有复活流程 | 每局激励复活最多一次，需新增限制 |

局内与结算的成功激励次数分别累计，跨天保留，跳过不降级，本次升级从下次生效。局内此前成功次数0 / 1～2 / 3～5 / ≥6，对应倍率2 / 4 / 6 / 8。普通领取入口在首次免费后延迟3秒出现，金额和可领取方式需明确可见。

结算6～10倍合计概率保持原表。金额比例定义为当前可用模拟余额除以下一个未完成档位门槛，限于0～1；冻结额不参与下一档概率计算。这一冻结后口径为本版补充约定。

| 金额比例 | 未看过 | 看过1～2次 | 看过3～5次 | 看过≥6次 |
| --- | --- | --- | --- | --- |
| 0% | 82.0% | 98.6% | 99.5% | 99.7% |
| 50% | 35.0% | 89.6% | 95.6% | 97.2% |
| 80% | 12.0% | 68.6% | 84.5% | 89.7% |
| ≥95% | 6.0% | 50.5% | 71.9% | 80.3% |

区间间平滑变化。原报告没有给出2～5倍、6～10倍内部完整权重，也没有给出具体平滑算法，实现前应补齐配置；不能把6～10倍合计概率当作10倍概率。

首次累计达到1,000之前：每组三消模拟奖励1.25～3，按有效游玩与累计预算调整。5 / 10 / 15 / 20 / 25分钟的累计消除预算参考为80 / 170 / 270 / 370 / 480，阶段补奖分别30 / 40 / 50 / 60 / 70，各一次。预算不是到点整笔发放；尾部每组可低于1.25，480预算耗尽仍未达标时每组2。

首次达到1,000后：每组三消1，停止未发阶段补奖；申请、冻结和模拟结算都不重启首次加速。基础局内5和结算10保持不变。原“每对”改成“每组”后，达标速度需重新验证，不承诺原来的达标时间。

## 5. 广告触发与活跃分层

自动广告候选节点为主线开局、下一关、失败重试、丰收礼包领取结束。尚未核实可用的每日挑战入口，本版不增加该入口。所有候选节点共用计时，一次最多一条，无日上限，不补弹错过的广告。

| 已解锁连续登录层 | 自动间隔 | 原方案激励类型替换比例 | 局内礼包：三消组数且有效时间 | 不等时间 |
| --- | --- | --- | --- | --- |
| 首日/未升层 | 90秒 | 0% | 11组且60秒 | 17组 |
| 第2天 | 60秒 | 10% | 9组且45秒 | 13组 |
| 第3天 | 45秒 | 20% | 7组且35秒 | 11组 |
| 第5天及以后 | 30秒 | 30% | 7组且25秒 | 9组 |

升层同时要求连续登录天数、上一活跃日前台15分钟、上一活跃日通关3局。前台时间包含广告和弹窗；有效游玩仅计可操作棋盘及思考，排除教学、暂停、广告、奖励中心、后台。自然日连续登录与真实经过时长分开计算。

首次150秒有效游玩保护；成功激励后30秒保护；主动结算激励完成额外免下一次开局自动广告。保护与间隔同时推进不累加，首次免费奖励不算激励成功。教学、提现页、弹窗和广告期间不插入广告。最后一组三消进入通关结算，待发局内礼包不得抢在结算前弹出。

自动广告中的视频类型不产生额外奖励，不增加主动激励成功次数。原方案0/10/20/30%的类型选择保留在设计表中；实际使用何种可自动展示的广告格式须按接入 SDK 的正式能力确定，不能将需要用户同意的激励入口强制播放。失败或提前关闭不立即补播另一条。

回流缺席1～2 / 3～6 / ≥7天，分别前180 / 300 / 300秒有效游玩使用110 / 120 / 135秒插屏间隔；缓冲期激励替换为0，局内门槛统一11组且60秒或17组。缓冲结束恢复历史层级，局内门槛从下一轮累计恢复。

原框架的按难度失败减压、提示道具补齐不能直接移植：本工程先保留已有撤销、魔法、洗牌、扩容与复活，不新增修改关卡难度的系统。这不改变提现链的核心。

## 6. 页面和玩家文案

首页和局内各提供一个标准 Button“丰收奖励”，通过 Prefab 配置视觉与交互。教学不弹奖励中心；首次达标引导等当前奖励、广告、动画和胜负流程结束，再显示一次。

奖励中心顶部展示“模拟奖励 · 不可兑换现金”，区分可用额和申请中冻结额；档位卡显示门槛和状态；申请页完整列出六站任务、阶段等待、168小时等待及最短13天，不能仅显示余额进度条。

| 位置/状态 | 标题或按钮 | 正文 |
| --- | --- | --- |
| 总入口 | 丰收奖励 | 查看丰收挑战与模拟奖励进度 |
| 教学礼 | 新手丰收礼 | 完成教学，获得20模拟奖励 |
| 局内 | 丰收礼包 | 本次可领取5模拟奖励 |
| 主动激励 | 看广告加奖 | 完整观看后领取本次显示的模拟奖励 |
| 普通领取 | 领取5 | 无需观看广告 |
| 达标 | 可以开启丰收挑战了 | 已达到本档模拟额度；完成六站任务与全部等待后模拟结算 |
| 申请 | 开启挑战（模拟） | 查看并确认完整挑战规则 |
| 阶段进行 | 收获积累 | 已完成{current}/{target}组三消；本阶段剩余{time} |
| 任务完成、时间未到 | 本站任务已完成 | 等待结束后开启下一站，无需继续完成本阶段任务 |
| 时间到、任务未完成 | 继续本阶段挑战 | 等待已完成，还需完成{remaining}组/局 |
| 最终等待 | 丰收结算倒计时 | 六站挑战已完成，剩余{time}；本流程为模拟结算 |

| 无广告 | 暂无可用广告 | 可领取基础奖励，稍后再试加奖 |

界面不得使用虚构的银行审核、物流发货、客服审批、排队人数或已到账通知。原宝箱保留独立的“关卡宝箱”名称，不混作提现资格。

## 7. 开发接入说明

以下为待实现点，不是已接通功能。

1. 配置层：新增 `HarvestRewardConfig` ScriptableObject，存放门槛、阶段、时间、倍率、概率、经济预算、活跃层和文案引用。阶段及状态使用稳定显式 ID，禁止依赖枚举字符串或反射。
2. 账本层：新增丰收余额、冻结额、首次赠礼标记、首次达标标记、两类激励次数、阶段补奖领取标记；与现有金币账本隔离。金额用整数最小单位。
3. 流程层：明确 `locked → eligible → stage_active → settlement_wait → completed`，阶段内部任务与时间独立记录。每个申请、关卡尝试、三消事件、奖励交易有唯一 ID，用于去重。
4. 玩法事件：在 `TryTripleMatch()` 的逻辑提交点统计三消；胜场使用 `LevelWin()`；不要在 `WinUI.BeforeOpen()` 发奖或记通关。恢复快照、重复打开界面和复活都不能重发既有收益。
5. 页面层：新建奖励中心、阶段卡、规则页和局内礼包 Prefab；在 `HomeUI`、`CorePlayUI`、`WinUI` 的已配置结构接入。全部可点击控件使用标准 Button，代码绑定事件；不沿用自定义点击组件来实现新按钮。
6. 广告层：将“有广告可点”和“广告完成且可发奖”拆开；SDK 完成回调携带请求 ID，只发一次奖励。当前 `AdButtonState` 与 `WinUI` 的直接回调不能作为正式实现。
7. 持久化：申请与奖励提交时保存，阶段存开始时间与进度；时间到只推进当前阶段，不自动补完未开启阶段。模拟版使用持久化 UTC 时间并处理时钟回拨；真实兑付版本必须另行设计服务端账本与可信时间，不能仅用本地余额。
8. 生命周期：后台、重启后恢复计时；UI 倒计时按秒刷新。所有逻辑在 Editor、Android、iOS 一致，不能写 Editor 专用领奖或广告成功兜底。

性能建议：推荐事件驱动的统计和按秒刷新的倒计时，UI/数值用轻量配置；大图、音效与特效按路径加载并复用。没有必要为每个水果创建奖励 UI，或每帧扫描场上水果统计任务，这会增加 CPU、GC、Layout 重建及加载峰值，本方案不采用。

## 8. 实现验收清单

- 教学赠礼和两类首次免费各只领取一次；首次达标后不可通过冻结、结算或重启恢复加速。
- 三个同类完成一次三消，只增加一组；重复动画、快照恢复和重复回调不重复记账。
- 六阶段任务量与等待同时满足才能推进；最短13天；后台与重启不重置进度。
- 无广告、广告失败、提前关闭不计成功次数；基础领取仍能完成；自动广告不计主动次数。
- 等待结束但任务未完成、任务完成但等待未结束均有正确文案；不偷偷增加条件。
- 主线、金币、宝箱、道具与首次免费复活原有数据不被覆盖。
- 标准 Button、Prefab 引用及真机一致性检查通过；实际 Android/iOS 广告与存档回归完成后才能标注上线可用。
